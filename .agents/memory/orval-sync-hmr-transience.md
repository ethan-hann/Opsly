# orval-sync HMR transience

## Rule
Never import symbols that are generated by orval (e.g. `getGetMyOrgQueryKey`) directly in app-layer hooks or components if a stable alternative exists.

**Why:** `pre-codegen.mjs` resets `lib/api-client-react/src/index.ts` to an empty string before regenerating it. During that window (milliseconds), Vite's HMR picks up the change and reloads the module — triggering a runtime error like "does not provide an export named 'getGetMyOrgQueryKey'" in any live browser tab. The error is transient but visible to users.

**How to apply:**
- For `refetchInterval`-style polling inside a hook that uses a generated query hook: use `useEffect` + `setInterval(() => refetch(), interval)` instead of passing `refetchInterval` inside `{ query: { ... } }` options (which required `queryKey` from the generated `getGet...QueryKey()` helper).
- If you must use a generated symbol that could vanish during reset, wrap the import behind a dynamic `import()` or accept the transient error.
- The generated hooks themselves (`useGetMyOrg`, `usePurgeCustomFieldDefinition`, etc.) are safe to import — only the helper functions like `getGet...QueryKey` and `getGet...QueryOptions` are risky.
